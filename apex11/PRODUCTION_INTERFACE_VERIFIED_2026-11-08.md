# ABUTRON → APEX 1.1.0: Production interface evidence and blockers

**Inspection date:** 8 November 2026, approximately 01:47–01:54 SAST (7 November 23:47–23:54 UTC). **Method:** read-only Remote Desktop Commander on production device `localhost`; read existing source, protected summaries, active worker native exports and timer inventory. **No platform files, services, account controls, broker orders or configs changed.** This document is an inspection record, not a deployment certificate.

## Confirmed source interfaces

- **Deriv:** `/opt/apex-client-mt5/native_apex_feed.py` reads trusted, account-bound `ABUTRON_NATIVE_ACCOUNT_V2_<nonce>.txt` plus `ABUTRON_NATIVE_BARS_V2_<nonce>.txt` from the isolated terminal's `MQL5/Files`, validates account ID/nonce and the 13-symbol × six-timeframe snapshot. Bar timestamps represent **M5 bar opening**, so close time is `open + 300 seconds`.
- **Deriv existing candidate router:** `/opt/apex-client-mt5/apex_signal_native_router_v1.py` loads per-account research inbox and requires scanner signal `proposal`, matching candle time, `signal_key = sha256(owner|connection|symbol|M5|bar_open|side)`, selective TradingAgents confirmation, ownership, entitlements, portfolio proof, client ON/OFF and handover. APEX 1.1.0 cannot be accepted by this router without an actual replacement of the candidate-verification logic. Do not bypass these independent account/broker/risk protections.
- **Deriv actual executor:** `/opt/apex-client-mt5/apex_native_order_runtime.py` handles native `.req` order files, immutable broker receipts, position evidence and ledger reconciliation. **Not invoked by this package.**
- **Deriv ledger:** `/opt/apex-client-mt5/customer_order_ledger.py` explicitly limits records to **Deriv DEMO**, not FP Markets, and has a state machine from RESERVED to SUBMISSION_UNKNOWN to broker ACK and protected/closed confirmation. Retain as the Deriv broker-native truth; FP needs a separate verified broker-native execution / ledger contract.
- **FP:** `/opt/apex-client-mt5/fpmarkets-feed/fp_feed_collect.py` verifies same-worker native account challenges, quotes/bars, clock offset, MT5 binary hashes and account-scoped symbols. A complete snapshot has schema `abutron.fpmarkets.native.candles.v1`; partial snapshots are explicitly not certified. It caps each timeframe at 70 bars. This prevents a 300-bar APEX warm-up on the currently exported FP feed.
- **Account identity and broker permissions:** isolated per-account MT5 workers with protected `worker-health.json`; agent snapshots alone do not prove a live broker authorization. A read-only bridge must never forge one.

## Incomplete by actual evidence, not by speculation

1. **Production cutover:** NOT DONE. Previous user instruction expressly prohibited deployment. No server writes or changes were made. Legacy and Qlib/Qwen services remain as they were.
2. **Native continuous history:** NOT READY. The inspected current Deriv export contains 100 M5 candles per symbol and FP exports are capped at 70, while the APEX candidate needs at least 300 warm-up bars. Require validated consecutive M5 history extending into the same live session; never concatenate Nov 1 history directly to Nov 7 with a time gap.
3. **FP broker clock:** NOT VERIFIED. `BROKER_CLOCK_OFFSET_UNVERIFIED` must be fixed from actual clock/tick provenance, not by hardcoding a guessed offset or accepting stale Forex weekend ticks.
4. **New candidate-to-MT5 order chain:** NOT EXECUTION-TESTED. Native Deriv router still verifies old scanner/TradingAgents and old signal hash, so only an authorized replacement of candidate verification can bridge APEX into its existing ledger. FP does not have the same order contract.
5. **Profitability:** NOT VERIFIED. The archived 400-bar Deriv snapshot was not imported into the local environment. There is no authenticated, identical-data APEX-versus-baseline, walk-forward, broker-cost-adjusted test for both brokers; no broker-acknowledged APEX-derived orders or realized P&L.
6. **Cutover/rollback:** Fresh offsite backup + complete source/DB readback + isolated restore proof, account switches, reconciliation, service dependencies and single-writer order ownership must be reverified before any authorized production replacement.

**Live trading remains out of scope without explicit separate authorization.** The last user instruction disallowing deployment remains in effect. This bundle is deliberately **offline-only and non-executing**.
